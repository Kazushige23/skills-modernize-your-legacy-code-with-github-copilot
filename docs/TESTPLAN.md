# Account Management Application Test Plan

このテスト計画は、現行 COBOL アプリケーションの業務ロジックとモジュール間連携を、Node.js 版の受入れ条件へ引き継ぐためのものです。各ケースは初期状態（保存残高 `1000.00`）から開始してください。連続操作を確認するケースでは、前のケースの結果を次のケースの事前条件として明記しています。

`Actual Result` と `Status` はテスト実施時に記入してください。`Status` は `Pass` または `Fail` のいずれかを使用します。

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TC-001 | アプリケーション起動時の初期残高を確認する | アプリケーションを起動する。保存残高を初期化する | 1. メニューで `1`（View Balance）を選択する | `Current balance: 1000.00` が表示される。残高は変更されない |  |  |  |
| TC-002 | 残高表示が保存残高を返すことを確認する | 保存残高が `1000.00` である | 1. `1` を選択する<br>2. 表示値を確認する<br>3. 再度 `1` を選択する | 2 回とも同じ現在残高が表示される。`TOTAL ` は `DataProgram` の `READ` を実行し、残高を更新しない |  |  |  |
| TC-003 | 入金で残高が加算され保存されることを確認する | 保存残高が `1000.00` である | 1. `2`（Credit Account）を選択する<br>2. 入金額 `250.00` を入力する<br>3. `1` を選択する | `Amount credited. New balance: 1250.00` が表示される。その後の残高表示も `1250.00` になる |  |  |  |
| TC-004 | 小数第 2 位までの入金を確認する | 保存残高が `1000.00` である | 1. `2` を選択する<br>2. `99.99` を入力する<br>3. `1` を選択する | 入金後の残高が `1099.99` になる。金額は小数第 2 位で扱われる |  |  |  |
| TC-005 | 入金額が 0 の場合の現行動作を確認する | 保存残高が `1000.00` である | 1. `2` を選択する<br>2. `0.00` を入力する<br>3. `1` を選択する | 現行 COBOL では入金が受け付けられ、残高は `1000.00` のまま保存・表示される |  |  | 0 を許可するかは Node.js 版の業務要件確認が必要 |
| TC-006 | 正常な出金で残高が減算され保存されることを確認する | 保存残高が `1000.00` である | 1. `3`（Debit Account）を選択する<br>2. `300.00` を入力する<br>3. `1` を選択する | `Amount debited. New balance: 700.00` が表示される。その後の残高表示も `700.00` になる |  |  |  |
| TC-007 | 残高と同額の出金を確認する | 保存残高が `1000.00` である | 1. `3` を選択する<br>2. `1000.00` を入力する<br>3. `1` を選択する | 出金が許可され、`Amount debited. New balance: 0.00` が表示される。残高は `0.00` として保存される |  |  | 境界条件: 判定は `FINAL-BALANCE >= AMOUNT` |
| TC-008 | 残高を超える出金が拒否されることを確認する | 保存残高が `1000.00` である | 1. `3` を選択する<br>2. `1000.01` を入力する<br>3. `1` を選択する | `Insufficient funds for this debit.` が表示される。`WRITE` は実行されず、残高は `1000.00` のまま |  |  |  |
| TC-009 | 拒否された出金後も後続操作が可能であることを確認する | 保存残高が `1000.00` である | 1. `3` を選択する<br>2. `1500.00` を入力する<br>3. `2` を選択する<br>4. `100.00` を入力する<br>5. `1` を選択する | 出金拒否後もメニューが継続する。入金が成功し、最終残高が `1100.00` になる |  |  |  |
| TC-010 | 0 の出金に対する現行動作を確認する | 保存残高が `1000.00` である | 1. `3` を選択する<br>2. `0.00` を入力する<br>3. `1` を選択する | 現行 COBOL では出金が許可され、残高は `1000.00` のまま保存・表示される |  |  | 0 を許可するかは Node.js 版の業務要件確認が必要 |
| TC-011 | 入金後の残高が後続の出金判定に使われることを確認する | 保存残高が `1000.00` である | 1. `2` を選択する<br>2. `500.00` を入力する<br>3. `3` を選択する<br>4. `1200.00` を入力する<br>5. `1` を選択する | 入金後残高 `1500.00` を基準に出金が許可され、出金後の残高が `300.00` になる |  |  | `READ` と `WRITE` の連携および状態保持を確認 |
| TC-012 | 出金後の残高が後続の入金に使われることを確認する | 保存残高が `1000.00` である | 1. `3` を選択する<br>2. `400.00` を入力する<br>3. `2` を選択する<br>4. `50.25` を入力する<br>5. `1` を選択する | 出金後の残高 `600.00` に入金され、最終残高が `650.25` になる |  |  |  |
| TC-013 | 無効なメニュー選択で業務操作が実行されないことを確認する | アプリケーションを起動し、保存残高が `1000.00` である | 1. `5` を入力する<br>2. 次のメニュー表示を確認する<br>3. `1` を選択する | `Invalid choice, please select 1-4.` が表示される。入金・出金・残高変更は発生せず、残高表示は `1000.00` になる |  |  |  |
| TC-014 | メニューの境界外の選択を確認する | アプリケーションを起動し、保存残高が `1000.00` である | 1. `0` を入力する<br>2. `9` を入力する<br>3. `1` を選択する | 各無効入力でエラーが表示され、操作は実行されない。最終残高は `1000.00` になる |  |  |  |
| TC-015 | Exit 選択でループを終了することを確認する | アプリケーションを起動する | 1. `4` を選択する | `Exiting the program. Goodbye!` が 1 回表示され、追加のメニュー入力を求めず終了する |  |  |  |
| TC-016 | Exit 後に残高操作が実行されないことを確認する | アプリケーションを起動し、保存残高が `1000.00` である | 1. `4` を選択する<br>2. プロセス終了を確認する<br>3. 終了後に残高操作が実行されていないことを確認する | `Operations` は呼び出されず、残高は変更されない |  |  |  |
| TC-017 | DataProgram の READ が保存値を呼び出し元へ返すことを確認する | `DataProgram` を単体で呼び出せる。保存残高が `1000.00` である | 1. `READ` と残高フィールドを渡して呼び出す<br>2. 呼び出し元の残高を確認する | 呼び出し元の残高に保存値 `1000.00` がコピーされる |  |  | Node.js ではリポジトリまたはストレージ層の read テストに対応 |
| TC-018 | DataProgram の WRITE が保存値を更新することを確認する | `DataProgram` を単体で呼び出せる。保存残高が `1000.00` である | 1. 残高 `1234.56` と `WRITE` を渡して呼び出す<br>2. `READ` を呼び出す<br>3. 返された残高を確認する | `WRITE` 後の `READ` が `1234.56` を返す |  |  | Node.js ではリポジトリまたはストレージ層の write/read テストに対応 |
| TC-019 | 未知の Operations コードの現行動作を確認する | `Operations` を単体で呼び出せる | 1. `UNKNOWN` を渡して呼び出す<br>2. 出力と保存残高を確認する | 現行 COBOL では何も表示せず、`READ`/`WRITE` も実行せず、残高を変更しない |  |  | Node.js 版では未知操作をエラーにするか、互換動作にするか要決定 |
| TC-020 | 入金の桁数上限を確認する | 保存残高が `1000.00` である | 1. `2` を選択する<br>2. 最大形式に近い金額 `999999.99` を入力する<br>3. 結果を確認する | 金額フィールドの形式 `9(6)V99` に従って処理される。オーバーフローや異常終了が発生する場合は記録する |  |  | COBOL の数値フィールド上限と Node.js の入力制限を合意する |
| TC-021 | 出金の桁数上限を確認する | 保存残高が `1000.00` である | 1. `3` を選択する<br>2. `999999.99` を入力する<br>3. 結果と残高を確認する | 残高不足として拒否され、保存残高は `1000.00` のまま。オーバーフローや異常終了が発生する場合は記録する |  |  |  |
| TC-022 | 不正な金額入力に対する現行動作を確認する | 保存残高が `1000.00` である | 1. `2` または `3` を選択する<br>2. 空文字、英字、負数などを入力する<br>3. 画面出力、終了状態、残高を確認する | 現行実装には入力妥当性検証がないため、入力形式ごとの実際の動作を記録する。少なくとも予期しない残高変更や異常終了の有無を確認する |  |  | Node.js 版では正数・数値形式・範囲外入力の扱いを業務要件として決定する |
